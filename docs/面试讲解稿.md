# 面试讲解稿（办公自动化 Agent）

> 用法：先背 30 秒版和 3 分钟版 → 理解“为什么” → 对着 10 个高频问题练。
> 核心心法：面试官考的不是“代码是不是你敲的”，而是“你懂不懂、能不能讲清、给你需求能不能接着做”。

---

## 一、30 秒版（脱口而出）

“我做了个办公自动化 Agent：员工用自然语言提需求，系统拆成子任务，按需调用邮件、日历、表格等工具执行；涉及发送、覆盖、删除这类高危动作，必须人工确认后才执行，做完给反馈。”

## 二、3 分钟版（按模块讲）

“技术上分四层：
1. **前端**（Vue）：对话页、待确认页、历史页、我的（邮箱绑定）
2. **后端接口层**（FastAPI）：任务、确认、用户、登录四组接口
3. **编排层**（agent）：LLM 把一句话拆成结构化子任务（动作/对象/高危标记/工具/参数），意图不明就反问，最多 3 轮
4. **执行与安全层**：工具层（邮件/日历/表格）按白名单执行；高危动作进确认闸门，确认落库、拒绝不执行、重复点击幂等

整个链路：登录（飞书）→ 输入 → 拆解 → 低危直接执行 / 高危待确认 → 执行 → 反馈。加上了日志、异常兜底、去重、参数校验，保证不崩、能查原因。”

## 三、10 分钟版（加设计取舍）

在 3 分钟版基础上补“为什么”：
- 为什么高危要人工确认？不可逆操作（发送/删除/覆盖）一旦错了代价大，确认是信任闸门
- 为什么表格用表头定位而不是让模型写行列？因为模型猜行列会写错列——真实踩过坑，它把“电话”写进了“备注”列，所以改成系统自己读表找“姓名/电话”表头定位，并写前预览
- 为什么拆解用 JSON + temperature=0？结构化输出好解析、低随机保证稳定
- 为什么去重 5 分钟、追问 3 轮？防重复执行、防死循环
- 为什么任务绑定用户？多人用不串账，历史/去重按用户隔离，确认防串账

## 四、核心机制原理（面试官最爱问）

### 1. 意图拆解
LLM 输出固定 JSON：`{"tasks":[{"action","target","params","high_risk","tool","args"}]}` 或 `{"tasks":[],"question":"..."}`。
意图不明 → 返回 question → 前端追问，合并上下文再提交；超过 3 轮返回“追问次数已达上限”。

### 2. 高危确认闸门
- 判定：关键词（删除/覆盖/发送/外发/更新/写入）+ 工具白名单
- 流程：高危子任务 → 建确认记录（pending）→ 前端确认/拒绝 → 确认后执行
- 幂等：同一确认重复 approve，第二次直接返回 approved，不重复执行
- 超时 30 分钟未处理 = 挂起，不自动执行

### 3. 表格按表头定位（重点讲，这是你踩过的坑）
用户说“把张三的电话改掉” → LLM 只输出字段名（key_column=姓名, key_value=张三, field=电话）→ **系统读表**找“电话”列、找“张三”行 → 定位 B2 → 确认页显示“将修改 报名表.xlsx：姓名=张三 的 电话（第2行B列），旧值→新值” → 确认才写。找不到表头/找不到人就报错，绝不瞎改。

### 4. 稳定与健壮性
- 统一异常处理器：未预期异常返回友好 500，堆栈写进 logs/app.log；debug 关闭（否则 Starlette 会绕过自定义处理器）
- SQLite 开 WAL + busy_timeout，防并发写锁
- 去重（同文本 5 分钟按用户复用）、白名单、参数校验、目录隔离

### 5. 邮箱绑定
发信邮箱优先级：用户绑定的邮箱 > 系统默认。授权码读取时打码；明文存库是 MVP 限制（后续加密）。

## 五、10 个高频问题及答案要点

1. **项目是做什么的？** → 30 秒版。
2. **技术栈为什么这么选？** → FastAPI 轻量快；Vue 上手快；SQLite 内测够用、预留 PostgreSQL；飞书 API + QQ 邮箱 IMAP/SMTP + 本地 Excel 都是你公司现有环境；DeepSeek 境内合规。
3. **意图拆解怎么做的？稳定吗？** → LLM 输出结构化 JSON；temperature=0 降随机；参数校验 + 白名单兜底。
4. **意图不明确怎么办？** → 反问（question 字段），最多 3 轮，防止死循环。
5. **高危动作怎么防误操作？** → 确认闸门 + 幂等 + 拒绝不执行 + 超时挂起；确认前文件/邮件无变化（有测试断言）。
6. **改表格怎么保证不改错列？** → 表头定位 + 写前预览；讲“备注列”真实踩坑。
7. **换模型 / 加工具要改多少代码？** → 换模型只改 llm/client 一处；加工具：新建一个文件 + 注册表登记，其它不动（插件式）。
8. **多人用会不会串？** → 任务绑定 user_id，去重/历史按用户隔离，确认跨用户 403。
9. **出问题怎么排查？** → 日志（logs/app.log）+ Trace（logs/traces）+ 统一异常；举个真实案例：后端进程断 → 前端代理返回 500 → 日志无记录 → 判断是链路问题。
10. **最大收获 / 踩过什么坑？** → ①改表格误改备注列 → 学到的：别让模型猜坐标，系统自己定位；②执行器新会话看不到未提交记录 → 复用当前会话；③--reload 监听 logs 触发重启 → 只监听代码目录；④跨端口 localStorage → 登录态走 URL 传递。

## 六、你的贡献清单（诚实版，面试就这么讲）

**你负责（讲清楚这些就是你的）**：
- 核心需求定义：自然语言 → 拆解 → 工具 → 高危确认 → 反馈 的完整流程
- 范围做减法：只留核心功能、砍掉付费等非核心
- 关键产品规则：高危动作必须确认、超时挂起、反问、授权码
- 技术选型拍板：飞书 / QQ 邮箱 / 本地 Excel / 飞书登录
- 验收与迭代：三场景验收、自动化测试框架（20 黄金 Case / 3 评分器）、改表格要识别表头的方向
- 我补的：代码实现、测试、文档、联调排错

**话术**：
“这个项目是我和 AI 结对开发的。我负责需求定义、架构决策、范围取舍、验收标准；AI 负责编码实现和测试。所以我能讲清楚每一步为什么这么做，也踩过真实的坑，比如表格改错列、执行器事务问题。”

## 八、如果被问“这里是不是 AI 写的代码？”

诚实回答 + 转移重点：
“是的，部分是 AI 生成的。但每个模块我都读过、改过、测过，能讲清原理和取舍。比如这个确认闸门，是我定的规则——高危必须人工确认、拒绝不执行、重复点击幂等；AI 只是把它实现出来。我认为面试考察的是我能不能设计和维护这个系统，而不是打字速度。”
