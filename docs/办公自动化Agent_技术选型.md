# 办公自动化 Agent 技术选型（定稿 V2）

> 已确认：办公平台 = 飞书；公司邮箱 = QQ 邮箱；表格数据 = 本地 Excel。
> 已核对飞书日历官方文档（2026-08-13）。
> 以下为 MVP 技术决策，全部可后续调整（不影响项目骨架）。

---

## 1. 定稿决策

| 项 | 决策 | 理由 |
|----|------|------|
| 前端框架 | Vue | 上手快，国内资料多 |
| 数据库 | SQLite 起步，预留 PostgreSQL | 内测够用，上线可换 |
| 日历 | 飞书日历 API（用户身份） | 官方支持，权限按人隔离 |
| 表格 | 本地 Excel/CSV | 数据在本地，实现最简单；以后可迁飞书表格 |
| 邮件 | QQ 邮箱 IMAP/SMTP | 公司邮箱是 QQ；读/发都支持 |
| 登录 | 飞书登录（默认） | 员工免注册；登录授权顺便拿到日历权限 |

## 2. 飞书日历接入要点（已核对官方文档）

| 要点 | 说明 |
|------|------|
| 调用身份 | 用 `user_access_token`（员工授权后以本人身份操作），只动自己的日程 |
| 权限申请 | ① `calendar:calendar:readonly`（读日历/日程）② `calendar:calendar`（建/改/删日程） |
| 建日程 | 分两步：先建日程，再调「添加参与人」接口（如 MVP 场景要带人） |
| 令牌 | `user_access_token` 会过期，需存授权并做刷新逻辑 |
| 忙闲查询 | 只能用应用身份（`tenant_access_token`）→ MVP 不做，放 P1 |
| 请假日程 | 有官方 API，但用户未提此需求 → 列为以后可做，不进 MVP |

## 3. 实施前置清单（建议第一周做）

1. **飞书**：开放平台建「自建应用」→ 申请权限（上面两个日历 scope + 用户信息）→ 管理员审批 → 配置登录
2. **QQ 邮箱**：内测员工开启 IMAP/SMTP 并生成「授权码」（≠登录密码，只存服务器）
3. **本地 Excel**：确定允许 Agent 读写的文件清单、格式（xlsx/csv）、样例路径
4. **内测名单**：≤50 人

## 4. 配置项（放 .env，不进仓库）

- 飞书：app_id、app_secret、redirect_uri（登录回调）、所需权限 scope
- QQ 邮箱：员工邮箱、授权码（IMAP/SMTP）
- 大模型：境内模型 API key

## 5. 风险（推测）

| 风险 | 对策 |
|------|------|
| 员工取消授权/离职 → token 失效，任务失败 | 清晰报错提示 + 引导重新授权 |
| QQ 邮箱授权码泄露 | 只存服务器 .env，最小权限 |
| 本地 Excel 多人同时写冲突 | MVP 小范围可接受；写前预览变更 |
| 飞书权限审批慢 | 第一周就提交申请 |
| 日后做「帮同事建日程」→ 越权风险 | MVP 严格限定只操作自己的日程 |
| QQ 邮箱接口细节（服务器/端口） | 接入时以 QQ 官方文档为准，不凭记忆写死 |
