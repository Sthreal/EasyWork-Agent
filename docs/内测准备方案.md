# 内测准备方案（最小版）

> 定位：MVP 内测，适合 1~3 人小规模验证。人数不够没关系——「自测 + 1 人盲测 + 自动化脚本」三件套即可。

---

## 1. 目标

- 验证三场景（发邮件 / 改表格 / 建日历）真实可用
- 验证稳定性：连续使用不崩、报错可查
- 收集真实反馈，修完 P0/P1 再考虑扩量

## 2. 最小内测模型（三件套）

| 手段 | 怎么做 | 价值 |
|------|--------|------|
| 自测 | 开发者按《三场景验收清单》完整跑一遍 | 确认功能可用 |
| 1 人盲测 | 找 1 个最信任的人，**不给说明书**，让他自己用 | 发现“用户不会用/说法千奇百怪” |
| 自动化 | 用冒烟脚本连跑 N 轮三场景，统计成功率 | 发现偶发 bug / 稳定性问题 |

> 真人多不多不重要：1 个盲测用户 + 自动化脚本 ≈ 完整内测。

## 3. 内测准备清单

| # | 事项 | 说明 |
|---|------|------|
| 1 | 环境 | 后端 8001 + 前端 5173 在自己终端启动（稳定） |
| 2 | 飞书 | 内测人员加入应用可用范围；登录授权一次 |
| 3 | 表格 | `Excel数据` 目录放样例表（Agent 只动这个目录） |
| 4 | 使用说明 | 一页纸：登录 / 发任务 / 高危确认 / 反馈方式 |
| 5 | 反馈登记 | `Excel数据\内测反馈.xlsx`（模板见第 6 节） |

## 4. 邮箱限制说明（必须先知道）

- 当前邮件是**单账号**配置：`.env` 里一个 QQ 邮箱 + 授权码
- MVP 内测：**统一用一个专用测试邮箱**（如 officeagent_test@qq.com），所有人的发信都从它发出
- “每人绑定自己的邮箱” → P1 功能，内测前不做

## 5. 内测流程

1. 自测：按《三场景验收清单》跑一遍，全过
2. 发使用说明给盲测用户，让他自由试用 1~2 天
3. 每次使用后（或每天）登记反馈表
4. 每日看反馈 → 修问题 → 按“改动不影响其它功能”回归（全量测试 + 冒烟）

## 7. 内测指标

| 指标 | 目标 |
|------|------|
| 三场景成功率 | ≥90% |
| 500 / 报错次数 | 连续 3 天为 0 |
| 高危确认流程 | 100% 走确认，无人绕过 |
| 反馈问题处理 | P0/P1 全部修复 |

## 8. 风险与对策（推测）

| 风险 | 对策 |
|------|------|
| 只有 1 个真人，覆盖不全 | 自动化脚本补足（连跑 N 轮） |
| 邮箱单账号限制 | 用专用测试邮箱 |
| 飞书应用审批慢 | 提前提交 |
| 内测数据保密 | 用测试数据，不用真实敏感数据 |
