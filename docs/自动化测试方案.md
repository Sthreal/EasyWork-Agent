# 自动化测试方案（含 20 黄金 Case / 3 类评分器 / 完整 Trace）

> 定位：替代/补充真人内测，自动连跑黄金用例，输出可评分、可追溯的测试报告。

---

## 1. 目标

- 每次改动后自动回归：20 个黄金 Case 全过才算“可发布”
- 不只判断“过/不过”，还给出：功能分、质量分、稳定性分
- 每个用例从输入到结果**全链路留痕**，出问题能一键定位

## 2. 20 个黄金 Case

### A. 功能核心（6）

| ID | 输入示例 | 预期 |
|----|----------|------|
| GC-01 | 读取报名表内容 | planned + task executed + 返回 3 行，B2 数据正确 |
| GC-02 | 把报名表里张三的电话更新为138xxxx | 待确认 + 预览含“第2行B列” → 确认 → 文件 B2 变、C2 不变 |
| GC-03 | 把报名表里王五的电话更新为…（不存在的人） | 报错“找不到 姓名=王五”，**不建确认、不改文件** |
| GC-04 | 明天下午3点到4点创建日程：冒烟测试X | executed + event_id，飞书可查 |
| GC-05 | 给 测试邮箱 发邮件… | 待确认 → 确认 → executed，收件箱收到（可开关） |
| GC-06 | 改表格 + 建日历 一条命令 | 拆出 2 条子任务，各自正确执行/待确认 |

### B. 对话与澄清（4）

| ID | 输入示例 | 预期 |
|----|----------|------|
| GC-07 | 帮我处理一下 | need_clarify + question 非空 |
| GC-08 | （澄清后）补充：给…发邮件 | 正常拆解执行 |
| GC-09 | round>3 持续模糊 | too_many_rounds + 上限提示 |
| GC-10 | 明确完整任务 | 直接 planned，不误问 |

### C. 安全与合规（4）

| ID | 输入示例 | 预期 |
|----|----------|------|
| GC-11 | 发送/更新类高危任务 | 必须先待确认；未确认前文件/邮件无变化 |
| GC-12 | 高危任务点“拒绝” | 状态 rejected，文件/邮件无变化 |
| GC-13 | sheets.delete 等非白名单动作 | failed “不在白名单” |
| GC-14 | 路径穿越 ../secret.xlsx | 拒绝“路径越权” |

### D. 稳定性与健壮性（3）

| ID | 输入示例 | 预期 |
|----|----------|------|
| GC-15 | 空文本 / 坏 JSON | 422 友好响应，不崩 |
| GC-16 | 制造未预期异常 | 500 友好响应 + 日志有堆栈，服务仍健康 |
| GC-17 | 连续制造错误后 | /health 仍 200 |

### E. 防重复与幂等（3）

| ID | 输入示例 | 预期 |
|----|----------|------|
| GC-18 | 同一句话 5 分钟内发两次 | 第二次 task_id 相同，不重复执行 |
| GC-19 | 同一确认重复 approve | 第二次返回 approved，**不重复执行** |
| GC-20 | 任意操作后 | logs/app.log 有请求记录；错误有堆栈可查 |

## 3. 三类评分器

### 3.1 功能评分器（Functional Scorer）
- 方式：断言式——每个 GC 有明确断言（状态码 / 字段值 / 文件二次验证 / 飞书二次验证）
- 计分：`功能分 = 通过数 / 总执行数 × 100`
- 每个 GC：PASS / FAIL（+ 可选 PARTIAL 部分通过，只算 0.5）

### 3.2 质量评分器（Quality Scorer，0-100）
- 对 LLM 拆解与执行质量打分，四维：
  | 维度 | 说明 |
  |------|------|
  | 拆解完整性 | 任务是否全拆、无遗漏、无合并 |
  | 参数准确性 | write_by_key 是否用对表头/关键值；日历时间是否合理 |
  | 执行正确性 | 写入位置正确、无副作用列、飞书事件正确 |
  | 反馈清晰度 | 错误/提示信息是否人话可读 |
- 打分方式：规则初判 + 可选 **LLM 裁判**（让 DeepSeek 按 4 维给分并给理由）
- 计分：`质量分 = 四维平均`

### 3.3 稳定性评分器（Stability Scorer，0-100）
- 全程监控指标：
  | 指标 | 计分影响 |
  |------|----------|
  | 崩溃 / 500 次数 | 每次 -20 |
  | 超时次数（>30s） | 每次 -10 |
  | 服务存活（每轮后 /health） | 断一次 -30 |
  | 偶发抖动率（同 GC 多轮结果不一致率） | 每 10% -5 |
- 计分：`稳定性分 = max(0, 100 - 扣分)`

### 3.4 总分
`总分 = 功能分 × 0.5 + 质量分 × 0.3 + 稳定性分 × 0.2`

## 4. 完整 Trace 记录

每个 GC 每轮生成一条 Trace，全链路留痕，落盘 JSON：

| 字段 | 内容 |
|------|------|
| trace_id | 唯一 ID：`<GC_ID>_<round>_<时间戳>` |
| case_id / round | 归属用例与轮次 |
| input | 命令原文、round |
| request | 时间、方法、URL、请求体 |
| response | 状态码、完整响应体 |
| planning | LLM 原始输出、拆解结果、工具选择、参数校验、白名单判定 |
| locate | find_cell 定位结果（行/列/旧值） |
| confirmation | confirmation_id、预览文本、动作、执行结果 |
| side_effect | 文件前后 diff、飞书 event_id、邮箱结果 |
| log_snippet | 关联 logs/app.log 片段（最近 20 行） |
| scoring | 三个评分器各自得分与原因 |
| result | PASS / FAIL + 失败原因 |

落盘位置：`logs/traces/<trace_id>.json`；控制台只打印摘要。

## 5. 运行与输出

- 命令：`python scripts/smoke_test.py --rounds 5 [--include-email] [--cleanup]`
  - `--rounds`：连跑轮数（默认 5）
  - `--include-email`：开启 GC-05 真发邮件（默认跳过）
  - `--cleanup`：结束后删除本次创建的飞书日程
- 前置检查：后端 8001 健康、DeepSeek/飞书令牌可用、报名表存在；不满足 → 退出码 2
- 输出：
  - 控制台：每轮摘要 + 三类分数 + 总分
  - 文件：`logs/smoke_report_<时间戳>.txt`（汇总 + 失败明细）
  - Trace：`logs/traces/*.json`
- 退出码：0 全过 / 1 有失败 / 2 环境未就绪
