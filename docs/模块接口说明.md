# 模块接口说明（谁能调谁）

> 用途：把模块边界从“代码约定”变成“文档契约”，多人协作时不踩线。
> 原则：**依赖只向一个方向流动**：`api → agent → tools / safety / llm / feishu → models / config`。

---

## 1. 依赖方向图（箭头 = 可以调用）

```
frontend
   │  (HTTP)
   ▼
api（auth / task / confirmation / user）
   │
   ├──► agent（planner / executor）
   │        ├──► llm（client / messages）──► config/prompts
   │        ├──► tools（email / calendar / sheets）
   │        │        ├──► tools/registry · tools/base
   │        │        └──► feishu（token）· models · db
   │        ├──► safety（gate / whitelist / high_risk）
   │        └──► models · db
   ├──► safety（gate）
   └──► models · db

models ◄── 所有模块（只被使用，不依赖别人，仅依赖 db）
config/settings · config/logging ◄── 全局配置（被所有模块读取）
```

## 2. 模块职责与依赖清单

| 模块 | 职责 | 可依赖（调用） | 禁止依赖 |
|------|------|----------------|----------|
| config/ | 配置、日志、提示词 | 无 | 任何业务模块 |
| backend/db.py | 数据库连接 | config/settings | api/agent/tools |
| models/ | 数据表定义 | db | api/agent/tools（仅被使用） |
| api/v1/ | HTTP 路由（薄层） | agent、safety、models、db、schemas | tools/llm 直接调用 |
| agent/ | 拆解 / 执行编排 / 反馈 | llm、tools、safety、models、db | api（不可反向） |
| tools/ | 工具实现 + 注册表 + 校验 | base/registry、feishu(token)、models、db、config | api、agent |
| safety/ | 高危判定 / 白名单 / 确认闸门 | models、db | api、agent、tools |
| llm/ | 大模型统一封装 | config/settings、config/prompts | api、tools、models |
| feishu/ | 飞书客户端 / 授权 / 令牌 | config/settings、models、db | api、agent、tools |

## 3. 允许的“穿透点”（已知、可控，改动需注意）

| 位置 | 为什么存在 | 改动注意事项 |
|------|-----------|--------------|
| agent/executor 直接查 models（Task/User） | 发信时按任务归属用户注入绑定邮箱 | 改用户表/任务表字段时，executor 也要回归 |
| tools/email 读 config/settings | 取系统默认发件邮箱 | 改 .env 邮箱配置只影响默认邮箱 |
| tools/calendar 依赖 feishu/token_store | 拿 user_access_token | 改令牌逻辑时，日历工具需回归 |
| api/task 依赖 safety/gate | 高危动作建确认记录 | 改确认流程时，任务接口需回归 |

## 5. 新模块接入步骤（照做）

1. 在 `backend/` 下建新目录（一概念一文件）
2. 确定依赖：只允许依赖箭头方向内的模块
3. 若被其它模块调用，先在 registry / 路由里注册
4. 补测试（镜像结构）
5. 跑全量测试 + 相关回归，再提交

## 6. 红线（违反即视为架构违规）

- ❌ models / config 反向 import api / agent / tools
- ❌ api 路由之间互相调用（应通过数据表或抽公共 service）
- ❌ tools 直接 import agent / api
- ❌ 在路由层写业务逻辑（应放 agent/safety/tools）
