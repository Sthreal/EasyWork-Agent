# 通用办公自动化 Agent MVP 定义（基于 PRD V0.3）

> 本文件只从 V0.3 的 P0 与默认设定中圈定 MVP 范围，未新增核心需求。
> 标「建议」的为补充建议，不阻塞 MVP。

---

## 1. MVP 一句话

员工用自然语言发起任务，Agent 拆解、调邮件/日历/表格执行，删除/覆盖/发送/外发必须人工确认，完成后给反馈。能跑通「发邮件、建日程、改表格」三个真实场景即算 MVP 达成。

## 2. MVP 范围

### 2.1 功能（P0 全部进 MVP）

| # | 功能 | 说明 |
|---|------|------|
| P0-1 | 自然语言输入 | 员工输入任务 |
| P0-2 | 意图拆解 | 拆成多个子任务 |
| P0-3 | 反问澄清 | 没听懂就反问 |
| P0-4 | 工具调用 | 邮件/日历/表格 |
| P0-5 | 高危确认 | 删除/覆盖/发送/外发 → 页面按钮确认，超时挂起 |
| P0-6 | 执行反馈 | 做完给结果反馈 |

### 2.2 默认设定（进 MVP 的部分）

| 事项 | MVP 做法 |
|------|----------|
| 登录 | 简单账号密码登录 |
| 权限 | 不限制，登录即可用 |
| 邮件 | 能读、能发 |
| 日历 | 能建、能改自己的日程 |
| 表格 | 能读、能写自己可见的文件，写前给变更预览 |
| 反馈 | 任务结束后汇总；失败说明原因 |
| 部分失败 | 其余继续，最后汇总成功/失败 |
| 审计 | 简单操作日志（谁、何时、做了什么） |
| 部署 | 内网/单机 + 境内大模型 |
| 规模 | 小范围内测（建议 ≤50 人） |

## 3. 典型场景（示例，用于验收）

1. **发邮件**：「给项目组发邮件，说明明天会议改到下午3点」→ 拆解：写邮件 → 发送（发送=高危，需确认）→ 反馈已发送
2. **建日程**：「帮我约明天下午和HR的会议」→ 拆解：查/建日程（改自己的日程）→ 反馈已创建
3. **改表格**：「把报名表里张三的电话更新为138xxxx」→ 拆解：定位表格 → 预览变更 → 写入（覆盖=高危，需确认）→ 反馈已更新

## 4. 里程碑（建议，可调）

| 阶段 | 内容 | 时间（默认） |
|------|------|--------------|
| M1 基础 | 登录 + 输入 + 意图拆解 + 反问澄清 | T ~ T+2周 |
| M2 工具接入 | 邮件/日历/表格 + 高危确认闸门 + 反馈 | T+2 ~ T+5周 |
| M3 闭环打磨 | 简单日志 + 三个场景联调 + 小范围内测 | T+5 ~ T+8周 |

## 5. 验收标准（MVP 完成 = 全部满足）

1. 登录后能用自然语言发起任务（P0-1/2）
2. 意图不明确时能反问，不瞎执行（P0-3）
3. 三个场景全部真实跑通：发邮件、建日程、改表格（P0-4）
4. 删除/覆盖/发送/外发四类动作必须弹确认，超时不确认挂起，挂起任务不执行（P0-5）
5. 任务完成后有汇总反馈；失败给出原因，且以工具真实返回为准（P0-6）
6. 每次操作留有简单日志（谁、何时、做了什么）

## 6. 明确不做（MVP 之后 / 不做）

- P1（以后做）：权限角色、完整审计、失败重试、进度逐步反馈、挂起提醒、定时批量、更多工具
- 非目标（不做）：IM 集成、无人值守全自动、跨部门复杂工作流、模型训练

## 7. 风险（推测，需在 MVP 内验证）

| 风险 | 程度 | MVP 内对策 |
|------|------|-----------|
| 工具误操作（删错/发错） | 高 | 高危必确认；先测试环境演练 |
| 拆错意图做错事 | 高 | 执行前展示子任务清单 |
| 假报成功 | 高 | 以工具真实返回为准 |
| 表格被误写 | 中 | 写前预览变更 |
| 越权/泄露 | 中 | 最小权限 + 简单日志 |

## 8. 下一步建议

1. 先定技术选型（默认：Python/主流Web框架 + 境内大模型API + 邮件/日历/表格API）（建议）
2. 按 M1 开始搭骨架，M2 接第一个工具（邮件）验证闭环（建议）
